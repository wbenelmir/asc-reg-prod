# Version 1.1 — UI work package 01

The header branding described here is superseded by [UI work package 02](v1_1_ui_02.md). Field alignment and status guidance remain in effect.

This work package improves form alignment, participant status guidance and
conference identity. It builds on the owner's version 1.0 production source.

## Resulting behavior

- Side-by-side standard fields share label and control tracks on modern
  browsers, including wrapped labels. Help text and errors appear below the
  controls and keep their accessible description links. On small screens,
  fields retain a natural single-column reading order.
- Submitted requests explicitly await acceptance. Under-review, draft,
  information-required, approved, not-approved and withdrawn requests each
  receive appropriate guidance. Existing identity-correction, rejection,
  withdrawal and origin-specific re-registration actions remain available.
- Registration details no longer present every historical request as a newly
  confirmed registration. Receipt-email status is taken only from that
  registration's submission acknowledgement, rather than a later decision or
  information-request message. Sent receipts are distinguished from acceptance.
- Every application shell displays the full conference name and the year 2026.
  The supplied conference artwork appears unchanged on the public authentication
  panel. Mobile pages retain the conference name and year even when that panel
  is hidden.
- New copy is available in English, French and Arabic. The institutional footer
  remains empty.

## Upgrade impact

No schema or data migration is introduced. No existing migration is edited.
The patch does not change registration decisions, role permissions, identity
verification, documents, consents, communication delivery or authentication.
An approval email and an invitation to register are separate from an invitation
to attend. These UI changes do not create an attendance-invitation delivery
workflow or claim that an invitation has already been sent.

Deploy the Python, template, stylesheet, image and compiled translation changes
together through the existing deployment procedure. Refresh collected static
assets and running application processes through that procedure. Preserve the
existing environment and production data.

## Acceptance checks

1. In English, French and Arabic, compare adjacent identity, contact and
   professional fields on desktop. Repeat with a long label, long help text,
   validation errors and enhanced searchable selects.
2. At 320px, 390px, tablet and desktop widths, verify readable controls and no
   page-level horizontal overflow. Repeat with JavaScript disabled.
3. Submit a synthetic registration and verify that the workspace and details
   explicitly distinguish receipt from acceptance. Follow all public statuses.
4. Verify that a later decision email cannot replace the displayed receipt-email
   delivery status, including when the receipt failed.
5. Verify identity-correction links and withdrawn/rejected re-registration actions
   for their own registration and origin. No participant sees another account's
   registration or internal decision reason.
6. Check public authentication, participant, wizard, operations, entry and error
   pages for the conference name/year. Confirm the supplied artwork retains its
   original proportions on its dark background.
